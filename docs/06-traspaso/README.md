# Traspaso — historia H5.8

Tres documentos, **tres lectores distintos**. Separarlos no es orden: es la única forma de
que cada uno se lea. Un solo documento que sirva al manager del hotel y a un programador no
lo lee ninguno de los dos.

| Documento | Para quién | Cuándo se usa |
|---|---|---|
| [**Cómo atender una solicitud**](runbook-operativo-solicitudes.md) | La persona del hotel que responde | **Todos los días.** Impreso o en el teléfono |
| [**Traspaso técnico**](traspaso-tecnico.md) | Quien mantenga el sitio después | El día que cambie de manos |
| [**Guion de capacitación**](guion-capacitacion.md) | Abraham, para dar la sesión | Una vez, y se graba |

## Los huecos, y están marcados a propósito

El runbook operativo tiene **espacios sin rellenar** y no es un descuido:

- El tiempo de respuesta comprometido (**B2**)
- Los porcentajes de IVA, ISH y saneamiento (**C3**)
- Quién atiende y quién lo suple (**B1**)

Se dejan visibles en vez de inventarlos, y se rellenan **en la propia sesión de
capacitación**, con el hotel delante. Un runbook con un dato inventado se descubre el día
que alguien lo usa; un runbook con un hueco se descubre al leerlo.
